# DriftWood v1.5.0 — the report stops guessing about what it could not read

## Summary

This release exists to close one failure class: reporting a number for something DriftWood did not actually read. In previous builds, a folder whose contents could not be listed came back as 0 B. A plain folder name with no matching installed app was called orphaned. A directory's modification date was folded into an `age_days` figure that the prompt described as "days since last use (or modification when last-use is unknown)". Those were defaults and heuristics wearing the costume of measurements, and the model reasoned from them as if they were data.

v1.5.0 makes the read state explicit — known, unavailable, or an error carrying a reason — and where the data is missing it holds the item at Source rather than rating it. It adds a hard, pre-model rule for OS-owned paths, and a Full Disk Access check so the scan can say why a protected folder was not inspected. The release is now cut by a GitHub Actions workflow on tag push; that is repository tooling and does not change the app.

## Features added

- **Full Disk Access is checked before the scan.** New `crates/driftwood-core/src/scan/fda.rs` opens the first existing TCC-protected directory (`~/Library/Safari`, then `Mail`, then `Messages`) at scan start. When macOS denies the listing, the scan emits a warning, the report carries a `full_disk_access` warning, and the Scan screen shows a "Full Disk Access not granted" panel with a button that opens System Settings. Before this, those folders reached the model as apparently empty.
- **OS-owned paths are hard-ruled to Source, without a model call.** New `crates/driftwood-core/src/system_paths.rs` is the single editable list: protected home locations, Apple daemon/service directory names (`Call*`, `Mobile*`, `AddressBook`, …), and the `com.apple.*` owner pattern. A match goes straight to Source before Stage 2 and costs no tokens. This consolidates the lists that were split between `hard_rules.rs` and `orphan.rs`, and extends them (MobileDevice, CallHistoryDB, CallHistoryTransactions, `com.apple.sharedfilelist`, IdentityServices, HomeKit, Sharing, Suggestions). The softer `com.microsoft.*` suite floor is unchanged.
- **An item DriftWood could not read is shown as "not inspected", not as a size.** A file or folder whose stat or sizing failed, or whose walk skipped entries, is marked `readable: false` with a `tier_source` of `not_inspected` and the reason ("not inspected (permission denied)"). It is held at Source by code, never sent to the model, and "Ask the river" is disabled on the card with that explanation.
- **The model's payload no longer spells missing data as zero.** Size, child count, and every date are sent tri-state: a real value when known, or `"unavailable"` / `"unavailable (<reason>)"` when not. Dates are labeled by source — `last_used` only when Spotlight recorded a use, `last_modified` and `created` as the filesystem fields they are. `age_days_since_last_use` is emitted only when last use is genuinely known; the old `age_days` fallback to modification time is gone.

## Bugs fixed

- **An unreadable folder was reported as 0 B.** When a folder's size task failed, timed out, or was never dispatched, the engine stored a zero size with a `truncated` flag and the UI rendered `0 B`. A folder's measure now carries a failed, partial, or known state: a failed root `read_dir` (the EPERM a TCC-protected folder returns) is an error, and a walk that skipped entries is a partial read marked `readable: false`. A zero is never claimed as a measurement.
- **A plain folder name was treated as an orphan.** `classify_orphan` returned `Orphaned` for any non-generic name with no installed-app match, so a folder like `MyOldDeletedGame` was orphaned on the strength of its name alone. Only a reverse-DNS name is now evidence of a former install; a plain name with no match is `Unknown`, and OS-owned names are never orphaned.
- **A timed-out app snapshot left orphan detection running blind.** If the installed-app snapshot timed out, orphan classification still ran against an empty app list and could mark folders orphaned. When the snapshot is not known, every item's orphan status is now `Unknown`.
- **A directory's modification date was promoted toward "last use" for the model.** The payload's `age_days` used Spotlight last-used, then modified, then created, and the prompt described it as "days since last use (or modification when last-use is unknown)". Missing usage is now labeled as missing.

## Breaking changes

None for app users. Your settings, saved rules, and last report carry over, and reports written by v1.4.x still load.

The report JSON is still schema version 2. It gained additive fields (`size_state`, `children_state`, `modified_state`, `created_state`, `last_used_state`, `readable`, `read_error`) and one new `tier_source` value, `not_inspected`. Reports persisted before these fields existed load because the new fields default to a fully-read item. Anything outside the app that parses report JSON should accept the new tier source.

## What did not change

- **DriftWood still deletes nothing.** The Finder hand-off is still the only thing that touches your files: it opens windows and sets selections, and the test that reads the production hand-off source and fails on `remove_file`, `remove_dir`, `rename`, `fs::write`, or `trash` is still in the suite and passing.
- Scan modes and deep read semantics, the cost cap and ZDR default, the auto-high rules, the Finder hand-off behavior, and every settings key are untouched. Report schema version is still 2.
- Tier precedence keeps the same shape — your rule beats the system-owned rule, which beats the floor, which beats auto-high / the AI / the heuristic. The one move is that the system-owned Source rule now sits between your rule and the floor; before this release the floor was the second check.

## Upgrade / compatibility notes

- Replace the previous app with this one. There is no migration and nothing to reconfigure — settings, saved rules, and the last report carry over.
- The app remains ad-hoc signed and not notarized (`signingIdentity: "-"`), so on first launch expect Gatekeeper's "unidentified developer" prompt; use right-click → Open.
- Minimum macOS is 10.15, unchanged from the previous release.

## Known issues / still broken

- Verification here is the test suite and the static check, not a live scan. I did not run DriftWood against a real permission-denied directory, so the Full Disk Access path is covered by its code and the UI logic, not by an on-device confirmation. `fda.rs` has no unit test; its `Denied` branch runs only when the permission is actually absent.
- Partial reads are coarse on purpose. A single unreadable entry holds the entire parent folder at Source as "not inspected", even when the rest of it was measured. This errs toward not rating something it could not fully see, but it can hold a folder whose size was almost entirely known.
- OS-owned matching is name-based. Under `~/Library`, a folder the user literally named `Sharing` or `Suggestions` is forced to Source without model judgment. The rule prefers protecting the wrong folder over exposing an Apple one.
- Repo hygiene: commit `99fa1b5` added a 1.7 MB screenshot at the repository root. It is not in the DMG and is not part of the app; it is left in place rather than rewritten out of history.

Build facts: 129 tests pass (105 in `driftwood-core`, 24 in the app library; 2 ignored), and `svelte-check` reports 0 errors and 0 warnings. The arm64 (Apple Silicon) DMG and its `.sha256` are attached to this release.
